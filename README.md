# p3k

CLI для локального окружения проекта и сайт про него.

**`p3k doctor`** отвечает на вопрос, ради которого всё затевалось: почему сервер
написал «ready», а страница пустая. **`p3k dev`** поднимает окружение по одному
конфигу и ждёт, пока каждый кусок начнёт отвечать. **`p3k check`** прогоняет те
же проверки, что потом прогонит CI. **`p3k init`** раскладывает каркас и пишет
этот конфиг.

Рантайм-зависимостей нет. Нужен Node 18 или новее.

```bash
npm i -g @busyburger/p3k

p3k init мой-сайт --template static
cd мой-сайт
p3k dev
```

## Что в репозитории

| Каталог | Что это |
|---|---|
| [`cli/`](cli) | сам инструмент — четыре команды, 43 теста, ноль зависимостей |
| [`src/`](src) | сайт проекта: Vue 3 + TSX, без UI-библиотек |
| [`starter/`](starter) | заготовка сайта на том же каркасе — копируется под новый проект |

Пакет публикуется из `cli/`. Подробная документация по командам и конфигу —
в [cli/README.md](cli/README.md) и на страницах сайта.

## Запуск

```bash
# инструмент
cd cli && npm install && npm run build && npm test

# сайт
npm install && npm run dev        # http://127.0.0.1:3000

# заготовка
cd starter && npm install && npm run dev
```

Сайт сам является потребителем инструмента: в корне лежит [`p3k.json`](p3k.json),
поэтому `node cli/dist/cli.js dev` поднимает его, а `check` прогоняет типы,
сборку и бюджет размера бандла.

## Состояние

Версия 0.1, ранняя разработка, пользователей пока нет. Написаны и работают
четыре команды; выкатка, превью-окружения на PR и генерация CI-пайплайна —
замысел, а не возможность. Полный список того, чего нет, лежит в разделе
«Границы» документации и в [известных ограничениях](cli/README.md).

Сборка и тесты идут на Linux, macOS и Windows под Node 18, 20 и 22. Ручные
прогоны шли под Windows: определение владельца порта на Unix проверяется только
автоматикой.
