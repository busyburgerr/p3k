# p3k для Go

Библиотека, а не обёртка над консольной утилитой: окружение проекта
поднимается **внутри вашей программы**, и вы держите его в руках — можете
дождаться готовности, прочитать логи, погасить в конце.

```go
import p3k "github.com/busyburgerr/p3k/go"
```

Зависимостей нет: только стандартная библиотека. Нужен Go 1.21 или новее.

## Зачем

Интеграционные тесты, которым нужны настоящие база и кэш, а не заглушки:

```go
func TestMain(m *testing.M) {
    cfg, err := p3k.LoadDir(".")
    if err != nil {
        log.Fatal(err)
    }
    env := p3k.New(cfg, p3k.WithOnly("postgres", "redis"))

    ctx := context.Background()
    if err := env.Start(ctx); err != nil {
        log.Fatal(err)
    }
    code := m.Run()
    env.Stop(ctx)
    os.Exit(code)
}
```

`Start` возвращается не тогда, когда контейнеры запущены, а когда база начала
**отвечать**: `pg_isready` сказал «готов», порт принял соединение, HTTP отдал
статус ниже 500. Разница между «запустили» и «отвечает» — это почти все
плавающие падения интеграционных тестов.

`Stop` гасит в порядке, обратном запуску, и снимает **всё дерево процессов**,
а не только то, что запустили сами.

## Что умеет

| | |
|---|---|
| `Load`, `LoadDir`, `Find` | прочитать `p3k.json`; `Find` ищет вверх по дереву |
| `New`, `Env.Start/Stop/Wait` | поднять окружение волнами и погасить его |
| `RunChecks` | прогнать проверки проекта: параллельно, с кэшем по содержимому входов |
| `Ship`, `Rollback`, `Releases` | выкатить на сервер, откатиться, посмотреть выпуски |
| `Resources`, `Compose` | каталог ресурсов и продакшен-манифест из него |

## Условия готовности

```go
p3k.Port(5432)                              // сокет принимает соединение
p3k.HTTP{URL: "http://localhost:4000/health"} // ответ ниже 500
p3k.Exec("docker exec db pg_isready -U postgres") // команда вернула ноль
p3k.Log("ready in")                         // строка появилась в выводе
p3k.Delay(2 * time.Second)                  // признание поражения
```

Своё условие — это реализация интерфейса `Ready`. Например, «в базе появилась
таблица», то есть миграции отработали:

```go
migrated := p3k.Exec(`docker exec shop-db psql -U postgres -c "select 1 from users limit 1"`)
env := p3k.New(cfg, p3k.WithReady("postgres", migrated))
```

`Port` спрашивает обе петли — и `127.0.0.1`, и `::1`. Служба, привязанная
только к IPv6, иначе считалась бы неготовой навсегда.

## Дерево процессов

Главная причина занятых портов после остановки: `npm run dev` — это оболочка,
которая запустила Node, который запустил сборщик. Убив оболочку, вы не тронули
никого из них.

- **Unix** — своя группа процессов, сигнал всей группе.
- **Windows** — объект задания с флагом «снять задание при закрытии». Он
  важнее, чем кажется: даже если саму программу сняли принудительно и ни один
  её обработчик не отработал, **ядро погасит детей**. Node-версия этого не
  может — там для этого нужен нативный модуль.

Проверено отдельным тестом с настоящим внуком, и контрольным опытом рядом:
без объекта задания тот же внук переживает остановку.

## Выкатка

```go
report, err := p3k.Ship(ctx, cfg, p3k.WithShipOutput(os.Stdout))
```

Новый выпуск заливается **рядом** с работающим; ссылка `current` переключается
одним движением, только когда всё готово. Не ответило на проверку здоровья —
ссылка возвращается назад сама, и это занимает столько же, сколько
переключение, потому что прошлый выпуск лежит рядом целиком.

```
/srv/app/
  releases/
    20260907-104233/   новый выпуск
    20260906-183001/   прежний, нетронутый
  shared/
    .env               секреты, остаются на сервере
    compose.yml        собран из resources
  current -> releases/20260907-104233
```

Цель — интерфейс `Target`. Готовых две: `SSHTarget` и `LocalTarget` (каталог на
этой же машине). Локальная не игрушечная: на ней проверяется весь цикл, включая
испорченный выпуск и откат, — и свою цель можно написать поверх готового
соединения или API вашего облака.

Секреты в конфиг не попадают: в `compose.yml` уезжают только ссылки вида
`${POSTGRES_PASSWORD:?…}`, а пароли лежат в `shared/.env` на самом сервере.
Первая выкатка без этого файла отказывается идти дальше и кладёт рядом
`.env.example` со списком того, что заполнить.

## Что проверено

45 тестов, из них настоящими запусками:

- окружение поднимается волнами, и зависимые не стартуют раньше своих;
- `Start` возвращается по готовности, а не по факту запуска;
- неудачный подъём убирает за собой всё, что успело подняться;
- команда остановки выполняется и для уже завершившихся разовых шагов —
  иначе за `docker compose up -d` никто не прибрал бы;
- дерево процессов не переживает остановку (с контрольным опытом);
- полный цикл выкатки на локальной цели: испорченный выпуск, откат, и сервер
  снова отвечает;
- каталог ресурсов: у каждого есть условие готовности и команда остановки,
  в проде порты стоят только на петле, а пароли не утекают в манифест.

Не проверено на живой системе: выкатка по SSH на чужой сервер. Ветка написана
и разобрана, путь отказа отрабатывает внятно, но на настоящем VPS не
запускалась — начинайте с `p3k.DryRun()`.

## Отличия от версии на Node

Одинаковый конфиг, одинаковые правила, разные сильные стороны.

| | Go | Node |
|---|---|---|
| Дерево процессов при жёстком снятии родителя | гасится ядром | переживает |
| Форма | библиотека: окружение внутри вашей программы | утилита командной строки |
| Команды `init` и `add` | нет | есть |
| Диагностика окружения (`doctor`) | нет | есть |

Ошибка, которую нашли здесь и которой не было видно в Node: Go экранирует
кавычки в аргументах по правилам компоновщика C, а `cmd.exe` читает `\"` иначе.
Из-за этого любая команда с кавычками — например, `minio server /data
--console-address ":9001"` — доезжала бы до оболочки искалеченной. Командная
строка на Windows собирается напрямую.
